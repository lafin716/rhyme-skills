# task-run — 큐에 모아 둔 작업 처리

인자: `$ARGUMENTS`
- 비어 있으면 `QUEUE.md`의 모든 항목을 처리한다.
- ID(`Q-2 Q-5`)를 주면 그 항목만, 우선순위(`높음`)나 종류(`버그`)를 주면 그 조건에 맞는 항목만 처리한다.

이 스킬을 호출한 것은 **큐에 적힌 작업을 구현하라는 승인**이다. 승인 범위는 각 항목의 요청과 완료 기준까지다. 커밋·푸시·배포·릴리즈는 프로젝트 지침이 정해 두었거나 사용자가 이번에 요청했을 때만 한다. 프로젝트 지침(CLAUDE.md·AGENTS.md 등)의 개발·검증 규칙이 이 문서보다 우선한다.

## 1. 큐 읽기

- 프로젝트 루트의 `QUEUE.md`(또는 프로젝트가 정한 위치)를 읽는다. 없거나 항목이 없으면 처리할 것이 없다고 알리고 끝낸다.
- 대상 항목마다 `.queue/<ID>/`가 있으면 읽는다. `NOTES.md`의 조사 시점 커밋 이후 관련 파일이 바뀌었으면(`git log <커밋>..HEAD -- <파일>`) 그 부분은 다시 확인하고 그대로 믿지 않는다.
- 작업 트리에 처리와 무관한 미커밋 변경이 있으면 건드리지 않고, 처리 범위와 섞이지 않게 주의한다.

## 2. 처리 계획

- **이미 끝난 항목**: 코드에서 완료 기준이 이미 충족되면 구현하지 않고 "이미 완료"로 처리한다.
- **확인 필요**: 항목에 `확인 필요:`가 있거나 요청이 모순되면, 처리를 시작하기 전에 해당 질문을 **한 번에 모아** 묻는다. 대답을 기다리는 동안 독립된 다른 항목은 진행해도 된다. 프로젝트 지침이 질문 없는 자율 진행을 요구하면 합리적으로 정하고 결정 기록 관례에 남긴다.
- **순서**: `의존:`을 먼저 지키고, 그다음 QUEUE.md의 순서(우선순위)를 따른다. 같은 파일을 고치는 항목은 이어서 처리한다.
- 항목이 여럿이면 처리 순서와 묶음을 짧게 알린다.

## 3. 구현

항목마다(또는 같은 파일을 고치는 묶음마다):
1. 준비 자료와 코드를 바탕으로 원인·변경 위치를 확인한다. 버그는 가능하면 실패하는 테스트나 재현부터 만든다.
2. 완료 기준을 충족하도록 구현한다. 요청 범위를 넓히지 않는다. 구현 중 발견한 별개의 문제는 고치지 말고 4단계에서 새 항목으로 큐에 넣는다.
3. 관련 테스트·검증을 실행한다. 큰 기능(여러 컴포넌트, 설계 결정 필요)은 `rhymework` 스킬이 있으면 그 절차로 처리해도 된다.
4. 결과를 **완료** / **실패** / **보류** 중 하나로 정한다. 완료는 검증을 통과했을 때만이다.

- 서로 독립된 항목이 많고 서브에이전트를 쓸 수 있으면 파일이 겹치지 않는 묶음끼리 병렬로 맡겨도 된다. 같은 파일의 동시 작성자는 하나이고, QUEUE.md는 리더만 고친다.
- 한 항목이 실패해도 멈추지 말고 다른 항목을 계속한다. 같은 방법으로 세 번 실패하면 그 항목은 실패로 두고 넘어간다.

## 4. 마무리 검증과 큐 정리

1. 모든 항목을 처리한 뒤 프로젝트의 전체 검증 명령(typecheck·lint·test·build 등, 지침 문서 → package.json scripts → Makefile 순으로 찾는다)을 실행한다. 실패하면 원인 항목을 찾아 고치거나, 고치지 못하면 그 항목의 변경을 되돌리고 실패로 바꾼다.
2. 프로젝트 지침이 변경 후 실행·빌드 확인을 요구하면(예: 앱 다시 빌드 후 실행) 그대로 한다.
3. **QUEUE.md 정리**
   - 완료·이미 완료 항목은 지운다. 그 항목의 `.queue/<ID>/` 폴더도 지운다(지우기 전에 경로가 `.queue/` 아래인지 확인한다).
   - 실패·보류 항목은 남기고 `- 결과: 실패 (2026-11-13) — 이유, 시도한 것, 다음에 할 것` 줄을 붙인다. 준비 자료에 새로 알게 된 것을 `NOTES.md`에 보탠다.
   - 구현 중 발견한 새 작업은 task-queue 형식으로 끝에 추가한다.
   - 항목이 하나도 남지 않으면 머리말만 남긴다. `.queue/`가 비면 폴더를 지운다.
4. 커밋은 프로젝트 지침이 정했거나 사용자가 요청했을 때만 한다. 할 때는 저장소 관례대로 하고, 메시지 본문에 처리한 ID와 제목을 적는다.

## 5. 보고

사용자 언어로 짧게:
- 완료한 항목: ID · 제목 · 바뀐 점 한 줄
- 실패·보류 항목: ID · 이유 · 남은 일
- 새로 큐에 넣은 항목
- 검증 결과(명령과 통과 여부, 남은 실패)
- 커밋 여부, 남은 큐 개수
